控制端面板：会话结束要有结论 + 整页可滚动 · 真机验收 · 2026-11-21 05:00 班
================================================================================

一、起因（真机上看到的两个洞）
  ① 面板只在子进程「不到 10 秒就退了」时说话。**长会话结束时一声不吭** ——
     用户自己关窗、被控端关机后控制端放弃重连（退出码 4）、客户端崩溃，
     这三种在面板上长得一模一样：没有任何提示。面板又是 GUI 子系统（没有控制台），
     屏幕上那点日志一关窗就没了，现场报修时无从取证。
  ② 上一轮给失败提示加了「日志尾部三行」。真机上控制端以退出码 101 结束后，
     提示有 6~8 行高，把「开始远程控制 / 开一个远端终端」顶到窗口下边缘之外 ——
     最后一次截图里按钮只露出上边缘 15 px，**提示把「再试一次」按没了**。
     720x520 是默认窗口尺寸，不是极端情况。

二、改了什么（三个提交，协议零变化，只动 crates/uulan-gui）
  · `547d939` 会话结束要有结论：
      - 纯函数 `session_end_note(code, secs)`：0 = 正常收工；**4 = 放弃重连**（明写
        「被控端可能关机/断网，可再点一次」）；3 = 被控端没接受注入；其它 = 异常结束
        带退出码；None = 被强制结束。时长由 `fmt_dur` 写成「1 分 5 秒」。
      - 会话结束后无论退出码是 0 还是非 0 都 `push_log` + 写状态栏；非 0 另弹 alert
        （带日志尾部三行与全文路径）。
      - 状态栏在会话进行中显示「· 会话进行中（已 N 秒）」。
      - `push_log` 同时追加到 `~/.config/uulan/gui-actions.log`（>64 KiB 轮转成 .1）：
        结论从此可以事后 grep，不再只活在内存里。
  · `1adfcc3` 提示自身封顶：提示文本放进 110 px 的 ScrollArea，「我知道了」留在外面。
    （真机复验：仍不够 —— 见下一条）
  · `3aea352` 整页可滚动：CentralPanel 内容整体进 `ScrollArea::vertical()`
    （`auto_shrink([false,false])`）。缩进整体 +4，跨行字符串 0 处
    （脚本断言 `skipped_in_string=0`），文案零改动。

三、真机验收（麒麟 :0，HEAD 构建的面板 `uulan-gui` sha256 前 16 位 `…` 见下）

四、「退出码 101」的真相（台架产物，不是用户路径）
  `xdotool windowclose` 走的是 **XDestroyWindow**（直接毁窗口，不通知客户端），
  winit 随后在自己窗口上取 GetGeometry 拿到 `BadDrawable`，`unwrap()` 直接 panic（101）。
  真实用户点标题栏的 × 走的是 WM_DELETE_WINDOW → winit 正常退出（本轮 `wmctrl -ic`
  复现了这条路：退出码 0、面板说「正常收工」）。
  两条都留着记录：前者是台架的坑，后者才是现场形态；顺带说明面板现在**能把这两种
  结局分开说**，而以前它们都表现为「窗口没了，什么都没说」。

六、面板二进制与机器状态
  · 面板：`~/.local/uulan/bin/uulan-gui`（本轮三次替换，备份 `uulan-gui.bak-0500`）；
    收尾用 HEAD 构建起的进程在 :0 上（单实例锁持有者）。
  · `~/.config/uulan/gui.json`：为了免手输口令做验收，曾预填
    「中继 + 设备 ID + 记住口令」；**收尾已还原**为本轮开始前的干净默认
    （relay 空、device 空、remember_pw=false、无 password 字段），面板按干净默认重启并
    截图确认正常。还原用的备份是 `gui.json.bak-0500`（本轮开始时创建，只在不存在时写）。
  · `gui-actions.log` 留在原处（只有动作与结论，无凭据），用户下次打开就能看到本轮轨迹。

七、仍未验
  · **多显示器布局**（这台机器只有一块能点亮的输出，合成不出第二块给面板）；
  · 面板在麒麟上的**拖动**只验了 `windowmove` 一次，真拖标题栏的手感未验；
  · OS 模式成功路径（需要 mis 的真实登录密码，只能由用户本人点一次）；
  · 会话进行中的时长刷新只在一次 38 s 的会话里读过，长会话（>1 h）未读。

八、复跑办法（台架是坐标驱动的，坐标必须现取）
  · 真机脚本（本轮留在 ~/ 下）：`gui_prefill.sh`（从 host.json 取口令预填 gui.json，
    口令不上屏）、`gui_click_start.sh`（点开始 + 拍图 + 看 gui-actions.log）、
    `gui_close_normal2.sh`（`wmctrl -ic` 正常关窗）、`gui_scroll_test.sh <BX> <BY>`
    （长提示 → 顶部拍图 → 滚轮下滚 → 底部拍图）、`gui_restore.sh`（还原 gui.json 并重启面板）。
  · 坑：① 有红字时整页下推，**按钮坐标必须按当前截图重取**；
        ② `xdotool search --name "uulan 内网远控"` 在 ssh 的 bash 脚本里偶发不命中，
           用 `xdotool search --pid $(pgrep -x uulan-gui)`；
        ③ 5 行 `Failed to open device`（Glenfly EGL 探测）是这台机器的固定噪声，不是故障；
        ④ 想判「面板说了什么」**优先看 `gui-actions.log`**（机器可查），截图只用来判布局。
