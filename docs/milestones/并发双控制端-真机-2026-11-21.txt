并发双控制端（Windows + 麒麟同连一台被控端）· 真机验收 · 2026-11-21 05:00 班
================================================================================

一、为什么补这一格
  历轮所有验收都是「一个控制端 ↔ 一个被控端」。而 M6 修过的那处崩溃
  （`free(): invalid pointer` → SIGABRT，栈顶 `XTestQueryExtension → _XReply`）
  只在**并发会话**下出现 —— 当时靠「同一场景连跑 2 次」间接覆盖，从没真的让
  两台控制端同时连进同一台被控端。这一格补的就是「第二个控制端进来会不会把
  第一个挤掉 / 把被控端打断」这件现场一定会发生的事（同一台机器被两个同事同时连）。

二、台架
  · 被控端：麒麟真机 192.168.223.15，正式用户单元（本轮已换成 HEAD 构建
    `uulan-host` sha256 前 16 位 `b354ef936fc9576b`，设备 ID 805747189 不变）。
  · 中继：真机系统单元（/opt/uulan，0.0.0.0:21116）。
  · 控制端 A：麒麟本地自编客户端（headless 70 s，`--inject-live "wait:8000; move:640,400"`）。
  · 控制端 B：Windows 侧 HEAD 构建（headless 70 s，`--inject-live "wait:12000; move:1200,700"`）。
  · 判据：两端各自的收工统计 + 被控端 journal 的**每会话** `键鼠事件统计` + 会话中途
    抓一张真机 `x11grab` 截图做逐像素比对 + 被控端 RSS 三次采样 + MainPID/NRestarts。

三、实测数字（05:12:12 起，两会话同时在跑 70 s）
  A（麒麟）：收到 AU 2097 / 解出 2096 / **解码丢帧 0** / 首帧 263 ms / 29.9 fps
  B（Windows）：**29.9 fps** / 丢帧 0（逐 30 帧打印「丢包 0」）/ 首帧 291 ms /
            被控端自报 30.00 fps / 平均码率 10772 kbps / 会话建立 1 条、断线接回 0 次
  画面：两端各自存的帧与被控端真机 `x11grab` 截图逐像素比对
        （4×4 块均值降采样，129600 样本）
        A、B 均 **corr 0.9999 / MAE 1.12（255 满量程 = 0.44%）**，两帧彼此一致。
        口径说明：历轮报的「平均绝对误差 0.48%」是 **MAE/255**；本轮若按平均亮度(93.7)归一
        会写成 1.20%，两者不是同一把尺子。对照：真机连拍两张相隔 5 秒的截图互比
        **MAE 0.00**（桌面完全静止），所以这 1.12 是编码/解码损失本身，不是「桌面在动」。
  输入隔离：被控端 journal 里两个会话各一条
        `键鼠事件统计 events=1 inject_errors=0 dropped_locked=0` —— 各自只数自己那条，
        B 的 `未送出 0 / 被控端拒绝 0`；注入顺序如设计（B 晚 4 s），收尾指针落在
        `x:1200 y:700`（B 的那一下）。
  稳定性：被控端 MainPID 1553675 全程不变、NRestarts 仍为 2、`is-active=active`；
        RSS 5572 → 16252 → 15616 → 14968 kB（会话中涨、收尾落回，无单调上涨）；
        journal 里 ABRT / invalid pointer / panic **0 条**。

四、台架自身的坑（值得记）
  第一版把 `--inject` 和 `--seconds 70` 写在一起，结果两条会话各 1 秒就收工：
  `--inject` 是**一次性动作**，脚本执行完就主动道别（被控端 journal 原话
  `会话结束 why=对端道别: 注入脚本执行完毕`），跟 `--seconds` 无关。
  要在「正在看的会话里」注入必须用 `--inject-live`（跑完不退出，按 --seconds 收尾）。
  —— 又一次「判据/台架错在先，别先怀疑产品」。

五、仍未验
  · 三台及以上并发（本机只有两条控制端可用），以及**同一被控端上并发做文件/终端/
    端口映射**（本轮只并发视频 + 一次移动注入）。
  · 两会话同时 `--audio` / `--mic` 的争用（音频通道是否互相拖垮）。
  · 并发下其中一个被控端/中继重启时的接回行为。

六、撤法
  本轮对真机只做了「换正式被控端二进制」这一处状态变更，撤法：
    备份 `~/.local/uulan/bin/uulan-host.bak-0505`（本轮替换前的二进制）
    → `cp` 成 `.uulan-host.new` 再 `mv -f` 回同名
    → `systemctl --user kill -s KILL uulan-host`（systemd 自己发信号，Restart=always 拉起）
    → 核 `MainPID` 变化、`is-active=active`、journal「已用原有设备 ID 上线」。
