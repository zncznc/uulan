二、音频状态（AudioWatch/AudioStop）真机 ✅（含一个测试排序 bug 修复）
────────────────────────────────────────────────────────────────────────
1) `cargo test --release -p uulan-client --test audio_path` 在真机首跑 **3 passed / 1 failed**：
   `missing_audio_capability_is_recorded_not_only_logged` 红。查源码坐实是**判据 bug 不是产品 bug**：
   文件把「这台机器没声卡才成立」的硬断言排在「有声卡就 SKIP」的分支**之前** —— 在麒麟上 SKIP 永远跑不到。
   （正是白天那条「被 SKIP 的分支等于没验」教训的镜像：**断言排在跳过前面，等于跳过形同虚设**。）
   修：SKIP 分支前移到断言之前（保留一条形同虚设检查之外的兜底断言）。修后真机 **4 passed / 0 failed**。
2) 叫停链路真机复现：控制端 `--ffmpeg` 指到不存在路径 + `--audio`：
   控制端统计 `音频状态 : 本机已请求停止（被控端回了 1 条 / 起不来 0 次）… 被控端已确认停止`；
   被控端 journal `音频已停止（控制端关掉的）` —— stop_acks 语义在真链路上成立。
3) 声学反向真采：真机 `paplay` 10s 440Hz 正弦 → Windows `--audio-save`：
   收到 175 帧 / 64276 字节 → 6.4s PCM、**峰值 4034**、错误 0；
   频谱 Goertzel 判据 440Hz/1000Hz = **1.1e11 倍**、440/300 = 1.8e8 倍 —— 收下的就是那个音。
   采集源回话 `pulse:alsa_output.usb-Generic_USB_Audio-00.analog-stereo-spdif-output.monitor`（真实 USB 声卡）。
   ⚠ 首跑假红教训：paplay 必须检查退出码 —— 第一次静默失败给出「峰值 0 但解出 7.0 秒」的
   **静音也自洽**的假象；opus 静音帧极小（34B/帧），字节数对不上（7KB/7s vs 64kbps）是穿帮点。
   另 ssh 非交互会话跑 paplay 要显式 `export XDG_RUNTIME_DIR=/run/user/$(id -u)`。

四、电源动作真机 ✅ —— 唯一预期要改代码的点，果然要改
────────────────────────────────────────────────────────────────────────
【暴露的问题】host.json 加 power_allow:["lock"] 后 `--power lock` 回「已采纳/已执行」rc=0 ——
但取证发现**什么都没锁**：`loginctl lock-session` 在被控端 systemd 用户单元的上下文里退出码 0，
`loginctl show-session 5 -p LockedHint` 仍是 no、屏保 dialog 不出现、画面均值不变。
（归档里「LockedHint 管不到 UKUI 屏保」的旧记录就此坐实到电源动作链路。）

【排查实证（全在真机上，判据=抓帧均值 + dialog 进程数 + GetLockState）】
· `org.ukui.ScreenSaver` 在 session-5 上有名字；gdbus introspect 出全套方法：
  Lock()/ShowScreensaver()/UnLock()/GetLockState()/LockByBlank(i)→b …
· `ukui-screensaver-command --lock` **段错误（rc=139）**，不可用。
· 当轮会话内 Lock() 调用只翻状态不显形 —— 事后查明是**屏保守护进程被白天测试残留卡死**
  （idle-delay=5 也从不触发，dialog 永不拉起，锁状态 true 而无 UI）。
· **整机重启后 daemon 复活**：开机即有 `ukui-screensaver-dialog --lock-startup`（麒麟桌面无操作即锁屏，
  属机器习惯，非 uulan 行为）；杀掉 dialog → state=false、均值 103.6（真桌面）；再调 Lock() →
  dialog=1、均值 77.1 —— **UKUI 的 D-Bus Lock 在健康守护进程上真锁屏，机理钉死**。

【代码改动（本轮唯一功能性改动）】crates/uulan-host/src/power.rs：
· `Exec` 新增 `Chain(Vec<Vec<String>>)`：有序回落链，第一个「起得来且退出码 0（或超宽限仍在跑）」算数，
  全败报最后一步、并把前面各步失败原因缀进 detail（现场要能看见「缺的是 gdbus」而不是只看到兜底的半句话）。
· Lock 的 unix 分支改为链：**gdbus 调 org.ukui.ScreenSaver.Lock（UKUI 原生，真机实测显形）
  → 兜底 loginctl lock-session（认 LockedHint 的 GNOME/KDE 等仍走通用路）**。
· 采纳口径**没有**挪窝：仍然只在 compose 一处判（Chain 只决定「哪一步的结果送去给它」）。
· Windows 分支与其他动作（Logout/Reboot/Shutdown）一字未动；测试钩子 power_test_program 仍是单 argv。
· 测试：更新 production_commands 的 Lock 断言（链形状 + 两步内容）；新增
  `chain_takes_the_first_step_that_works_and_keeps_earlier_failures`（真程序 /bin/false→/bin/true 采纳；
