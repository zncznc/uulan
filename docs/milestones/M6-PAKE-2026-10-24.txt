二、这一轮做了什么
------------------------------------------------------------
M6 只剩最后一项：**主动 MITM 的中继能拿口令证明离线撞字典**。根因是不认证的 X25519
握手 —— 中继各连各的握手，同时拿到两份主密钥，于是它既能解密全部流量，又拿着
HMAC 证明去离线校验每个口令猜测。

改成 CPace（balanced PAKE，Ristretto255）：

  控制端                                            被控端
    G = H2G(DSI‖sid‖口令)                             G_i = H2G(DSI‖sid‖候选_i)
    Ya = G^x      --PakeInit{ya}-->                    （每个候选各一个点）
                  <--PakeResp{yb_0..yb_n}--           Yb_i = G_i^y
    K_i = Yb_i^x                                      K = Ya^y
  会话密钥 = HKDF(X25519 共享点 ‖ K)                  同左（只有命中的那个 i 相等）

关键决定：
1. **零新依赖**：只用 `curve25519-dalek`（本来就在依赖树里，是 x25519-dalek 的底层）
   的 Ristretto255 与 `from_uniform_bytes`（官方哈希到群）。内网离线打包不多带任何东西。
2. **sid = 加密握手的转录哈希**：不绑的话，两次会话的点可以互相剪接。
3. **多候选不改协议形态**：被控端有「永久口令 + 临时码」两个候选，PAKE 之后证明里
   不再含口令、也没法拿口令逐个试算 —— 所以改成「控制端把每个候选次序各算一把密钥、
   各给一份证明」，被控端拿自己那一个共享点核对，命中序号由 `AuthOk.idx` 回传。
   `Auth` 从 `proof: String` 变成 `proofs: Vec<String>`，条数必须等于候选数（否则直接拒）。
4. **鉴权通过后三通道原地换密钥**：控制通道用 `rekey()`（换密钥 + 计数器归零，
   新密钥下同一个计数器值不会撞 nonce）；**绝不能**重建 `SecConn` —— 同一把密钥重建
   会让计数器归零，那是 nonce 重用。视频/bulk 还没开始用，直接用最终密钥建。
5. 版本：`PROTO_VERSION 2→3`、`CRYPTO_VERSION 1→2`。旧端在 `CryptoHello` 阶段
   就被 `BadVersion` 挡掉，不会出现「一半新一半旧」的半加密状态（实测：先用旧客户端
   连新服务端 → `ProtoMismatch 服务端协议 v3，控制端 v2`）。

------------------------------------------------------------
① Windows 控制端，永久口令，12s headless：
   解出 355 帧 / 丢帧 0 / 首帧 227ms / 29.6 fps / 被控端自报 30.00 fps / 9782 kbps

   （与 PAKE 之前的 0.9980 / 0.71% 同一水平 ⇒ 密钥派生改动没影响画面通路）

② 麒麟本机编出来的控制端（同一条真链路）：
   解出 356 帧 / 丢帧 0 / 首帧 256ms / 29.6 fps / 被控端自报 30.00 fps / 9768 kbps

③ 错口令：`被控端拒绝：密码不正确`，被控端 journal 记 `鉴权失败 failures=1`，
   临时码未被消耗（配置里仍在）。

④ 临时码（**另一个进程**写的码，走热加载 + PAKE 候选序号 1）：
   - `uulan-host --new-temp-code`（短命进程写 host.json）
   - 第一次用新码：连上，29.2 fps，journal `鉴权通过 used_temp_code=true cred_slot=1`
   - 同一个码第二次：`密码不正确`，journal `鉴权失败 failures=1`
   - 永久口令随后仍可用：`鉴权通过 used_temp_code=false cred_slot=0`，29.0 fps
   （这四条同时成立，才说明「命中第几个候选」这条新链路真的通了。）

⑤ 日志脱敏没被这次改动破坏：`journalctl --user -u uulan-host` 最近 2 小时 122 行里
   `password_hits=0`（口令/临时码都不落日志；只落 `cred_slot` 这个序号）。

------------------------------------------------------------
五、仍然没验 / 已知限制（照实写）
------------------------------------------------------------
- **PAKE 实现是本仓库自己写的**（`crates/uulan-protocol/src/pake.rs`），没有第三方审计。
  用到的都是成熟原语（Ristretto255 哈希到群、常数标量乘、SHA-512/256 域分隔），
  但「自研密码学」这件事本身要写进现场文档，别当成经过审计的东西卖。
- **只做平衡式 CPace**：双方都要知道口令。不做「恶意被控端」这类更强模型。
- **锁定策略不变**：PAKE 把「离线撞」变成「在线撞」，口令强度与 `AUTH_MAX_FAILURES`
  仍然决定实际强度（临时码 8 位随机 + 5 次即锁）。
- 整机重启后的自启、root 系统装（/opt/uulan）仍是老样子：**未验**（本机 sudo 要口令，
  重启需要人到场登录）。
