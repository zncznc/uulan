## 揪出的 5 个脚本自身 bug（全部是「判据/工具坏了」，不是产品坏了）

1. **`BIN` 默认值里的 `~` 被本地展开**
   `BIN=${UULAN_BIN:-~/.local/uulan/src/target/release}` —— `BIN` 是要拼进**远端**命令串的，
   `~` 却在本地先展开成 MSYS 家目录 `/c/Users/chaoc/...`，远端路径当场作废。
   表现是「FAIL 真机上没有当前二进制」的假 FAIL，只有手动传 `UULAN_BIN` 才跑得动。
   修：默认值写成 `\$HOME/...`，把展开留给远端 shell。

2. **同一行 `local` 互相引用 → `set -u` 报未绑定**
   `local nm=$1 f="$WORK/ms-$nm.pw" pw=""` —— bash 先把整条 `local` 的词表展开完再赋值，
   所以 `$nm` 取的是**外层**同名变量（这里不存在，`set -u` 直接炸）。
   脚本死于半途，留下 Xvfb :97、两个 xev、测试中继、测试被控端**孤儿进程**。
   修：拆成两条 `local`。

3. **C 段命令串多一个重定向 + 双反斜杠**
   原写法 `… 2>&1; echo RC=\\$?>"`：两个反斜杠让 `$?` 在**本地**展开，多余的 `>` 使远端
   收到 `echo RC=<本地码>>` —— 尾部重定向没有目标，远端语法错误，诊断文件根本不生成。
   于是「FAIL×9」其实不是 9 个真 FAIL，而是 `|| echo 9` 兜底哨兵冒充的数据。
   **这行之所以从没暴露，是因为 C 段长期被 SKIP**（见下）。修：单反斜杠、去掉 `>`。

4. **`grep -c … || echo 9` 把「0 个」变成哨兵 9**
   `grep -c` 数到 0 个匹配时退出码是 1，于是兜底值 9 顶掉了健康的 `0` ——
   「一个 [FAIL] 都没有」被报成「FAIL×9」。修：显式区分「文件在不在」和「数到几个」，
   不再用哨兵冒充数据。（`|| true` 那种无害，全仓库只有这一处用了会伪装成数据的哨兵。）

5. **收尾判据自匹配**
   `ps -u mis -o args | grep -c "$RDIR"` 会数到**执行这条命令的远端 shell 和 grep 自己**
   （它们的命令行里就带着这个目录名），于是「清干净了」永远显示「残留 1~3 条」。
   修：改用带方括号的模式（`[X]vfb`、`[/]tmp/...`）让模式不匹配自身，并且把 Xvfb/xev
   也算进判据（它们的命令行里没有目录名，旧的判据根本看不见它们）。

另外把 C 段的**跳过条件改成按形态分支**：原来「真 :0 有 ≥1 块已连接输出」就整段 SKIP，
实际这台机器现在挂了 VGA-0，走的正是「索引越界 → 退回第一块」这条降级，同样必须钉住。
现在 0 块已连接 → 钉「空表降级（按整帧缓冲抓）」；≥1 块 → 钉「显示器1 不存在 → 退回第一块」。
顺带在开跑前加了一次陈旧测试台清扫，避免上一轮中途死掉的残留把新一轮 Xvfb 顶掉、
再被误报成「被控端没起来」。

## 两条教训

1. **被 SKIP 的分支等于没验，而且它后面的 bug 会一直藏着。** 上面第 3 条就躲在 SKIP
   背后：代码写了、看着挺全，但从来没执行过一次。一旦把 SKIP 打开，立刻现形。
   凡是 `SKIP` 的理由，都要问一句「这个理由是不是在替我掩盖没验的部分」。
2. **判据坏了比功能坏了更危险。** 今天 5 个 bug 里 4 个是判据/工具问题，它们全都以
   「功能有缺陷」的面目出现（假 FAIL），也全都会在反向情形下**把真缺陷藏进噪声**。
   遇到红，先问「这个数是怎么数出来的」，尤其当被比较的值本身看起来是对的。
