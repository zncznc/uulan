生成时间：2026-11-20 05:4x

一、为什么做这两件（都不是新功能）
  11-19 白天上线了「系统账户 + 登录密码」（OS 模式）与不经中继的直连，11-20 01:00 班又把
  被控端那一屏写成「对方怎么连我」。至此**用户要的形态已经齐了**：填 IP、填用户名和密码、点连接。
  但「控制端面板 → uulan-client」这条缝**没有任何机器可查的证据**：面板不接管画面，它只是
  spawn 同一个控制端二进制，于是「面板能不能用」整个落在那份 argv 上。而 GUI 子系统没有控制台 ——
  参数错一个，现场只看到「点了没反应」，日志里什么也没有。
  本轮就是来验这条缝的。一验就掉出三个真问题（前两个是面板的，第三个是被控端的）。

二、Bug ①：OS 模式下面板必挂 —— 空口令文件 + 无条件 --password-file
  面板原来无条件 `write_pw_file()` 写一个**空文件**，再把 `--password-file <空文件>` 递给控制端。
  用口令/临时码时没问题；但 OS 模式（用户名 + 系统登录密码）**根本没有访问口令**，
  控制端在解析参数阶段就退出：
      $ uulan-client --direct 127.0.0.1:21971 --password-file <空文件> --os-user mis ...
      Error: --password-file 的第一行是空的：.../empty.pw
  （本轮用真 exe 复现，见第三节。）
  这正是用户会走的那条路：麒麟 host.json 现在是 auth_os=true + pam.allow_users=["mis"]，
  Windows 面板上填直连地址 + mis + 登录密码，就是「填了用户名密码点连接」。旧版本必挂。
  修法：`route_args(..., pw_file: Option<&Path>)` —— **没有口令就不发 --password-file**，
  也不写那个空文件（顺带少一份明文副本）。

三、Bug ②：直连时仍强制要设备 ID（而提示自己写着「那时不用设备 ID」）
  `launch()` 里「还没填设备 ID」的检查排在直连判断之前，且不看直连是否已填。于是照着它自己的
  提示去做（填直连、不填设备 ID）的人一定过不去。修法：`direct.is_empty() && device.is_empty()`
  才拦。

四、Bug ③（被控端）：拒绝 OS 模式时只说给自己听
  被控端发现「控制端要系统账户认证、这台没开（或 PAM 没开）」时，只在 journal 里写一句
  `控制端要求系统账户口令认证，但这台未启用`，然后把连接一关。控制端那边看到的是
  `握手期间被控端断开` 或 `远程主机强迫关闭了一个现有的连接` —— **一条配置问题被伪装成网络问题**，
  现场按这个方向会去查防火墙。
  修法（`crates/uulan-host/src/session.rs`）：拒绝时**加密**回一帧 `H2C::Bye{reason}`，并且
  ① 原因分两种配错说（没开 OS 模式 / 开了但 PAM 没开），② 发完要把对端在途的字节**读干**再收尾。
  第二条不是洁癖：第一版发完就关，Windows 上带未读数据关 socket 会回 RST，排队中的 Bye 当场被
  丢掉，控制端拿到的仍是「远程主机强迫关闭了一个现有的连接」——本机台架实测撞到，才补的这一段。
  现在控制端是这一句：
      被控端拒绝：这台被控端没有启用「系统账户」认证，它认的是临时码/口令。请改填临时码/口令；
      要让系统账户能登录，得让管理员在被控端用 --auth os 并开启 --pam。

五、可测性：`uulan-gui --print-args`（+ `--argv-out <文件>`）
  新增一个**不建窗口、不连网、不抢单实例锁**的入口，把「面板会怎么跑控制端」原样打出来：
  屏幕上只打**脱敏后**的形状（口令文件路径抹成占位符），`--argv-out` 把逐行的原始 argv 落盘给脚本用。
  关键点：它与真正点按钮走**同一段** `prepare()`（校验 → 写凭据文件 → 拼命令行）。
  如果 dry-run 单独写一套拼装，脚本验过的形状就不是按钮跑的形状，验了也不算数。
  口令与系统密码只从环境变量 `UULAN_GUI_PASSWORD` / `UULAN_GUI_OS_PASSWORD` 取，不进 argv
  （与面板本身同一条纪律）。
  它同时是现场诊断工具：报「点了没反应」时，第一件要知道的就是子进程到底拿到了什么。

六、证据（`scripts/verify-gui-args-e2e.sh`，本机真三 exe：真中继 + 真被控端 + 真控制端 + 真面板）
  **18 通过 / 0 失败**，三个用例：
  A 经中继 + 口令：面板拼出的 argv 直接拿去跑控制端 → `已连上「e2e-host」`、收到 AU **22519** /
    解出 **22513** / 丢帧 **0** / 首帧 **234 ms**（6 秒会话）；控制端退出码 0。
    同时断言 `--print-args` 的屏幕输出里**搜不到口令原文**（脱敏生效）。
  B 直连 + 系统账户（不给访问口令）：argv 里**没有** `--password-file`、有 `--os-user` 与
    `--os-password-file`；控制端越过参数解析，拿到被控端回的原因（含「系统账户」）。
    反面对照：手动递一个空口令文件 → 仍然在参数阶段退出（把本脚本要挡的形状钉死）。
  C 直连 + 空设备 ID：表单放行、argv 里只有 `--direct`；经中继 + 空设备 ID：表单拦下（退出码 2，
    理由提到「设备 ID」）。
  脚本自身第一版有两处假红（统计行是 `  收到 AU    : 22519`，按单空格 grep 抓不到；B 案原本只认
  「密码不正确/不允许连接」两种文案）—— 已改为按冒号位置解析数值、按「原因里提到系统账户」判。

六点五、台架收尾：`scripts/kill-pid.py`
  第一版验收脚本收尾用 MSYS 的 `kill`，结果条条「执行了」却没杀掉 —— 收工后台上真留着
  **两个 uulan-host**（占着 21117）与**一个 uulan-gui**（占着单实例锁，后续 smoke 直接被挡）。
  无人值守会话里 `taskkill /F`、`Stop-Process -Force` 都会被命令守卫拦下，所以补一个小工具：
  `python scripts/kill-pid.py <pid>…` 走 Win32 `TerminateProcess`（不需要提权，只能杀本用户有权限的）。
  验收脚本的 `trap` 现在 kill 之后再用它兜一次；这一条对所有台架脚本都适用。
