--------------------------------------------------------
一、本轮解决的问题：控制端在麒麟上编不出来
--------------------------------------------------------

现象（改前，真机实测）：
  cargo build --release -p uulan-client
  → pkg-config exited with status code 1
     Package x11 was not found ... The system library `x11` required by crate `tiny-xlib`

根因：麒麟源里 libx11-dev 装不上（dev 包依赖 libx11-6 = 2:1.6.9-2kylin1.2，
系统里是 2:1.6.9-2kylin1.6，dev 落后一个 revision，apt 一律「无法修正错误」）。
于是 x11.pc / X11/*.h / libX11.so 全都不存在。两条独立的路都会踩到：

  A) softbuffer 的默认 X11 路径 = tiny-xlib 链接期找 X11 + pkg-config 读 x11.pc
  B) uulan-clip / uulan-host 的 #[link(name = "X11")] / #[link(name = "Xtst")]
     要链接期有一个叫 libX11.so 的文件（系统里只有 libX11.so.6）

修法：
  A) crates/uulan-client/Cargo.toml 的 cfg(unix) 段：softbuffer 加 x11-dlopen 特性
     （= tiny-xlib/dlopen + x11rb/dl-libxcb）。libX11/libxcb 变成运行期 dlopen，
     构建期不需要任何 X11 开发文件。副作用只有一条：运行时要 libX11.so.6/libxcb.so.1
     在，而桌面环境自己就在用它们。
  B) 新增 crates/uulan-clip/build.rs 与 crates/uulan-host/build.rs（同一份逻辑，
     host 多要一个 Xtst）：系统里没有 libX11.so 时，在 $OUT_DIR/x11-link/ 里把
     libX11.so.6 软链成 libX11.so，再 cargo:rustc-link-search=native=<该目录>。
     不需要 root、不改系统目录。系统里本来有 .so 时什么都不做；非 Linux 构建机空转。

B 的机制验证（本机真机，合成 crate，避免「以为行」）：
  /tmp/lt 里一个只有 #[link(name="X11")] + XOpenDisplay 的小程序，
  build.rs 把一份 libX11 拷贝软链成私有 shim/libX11.so；
  RUSTFLAGS=-C link-arg=-Wl,-t 编译，链接器打印的加载路径是
    /tmp/lt/target/debug/build/linktest-…/shim/libX11.so
  即 -L 私有目录确实排在系统目录之前、-lX11 从它解析；程序运行 XOpenDisplay(NULL) 正常。
  **未验**：把系统里那份 libX11.so 真的删掉之后的整仓首编 —— 删它要 root。

  （painted 是**客户端自己数的呈现帧数**，不是「解出帧数」——这条是 M2 验收口径）

逐像素比对（M2 那套方法）：
  真机截图：DISPLAY=:0 ffmpeg -f x11grab -video_size 1920x1080 -i :0 -frames:v 1 -y /tmp/shot2.ppm

  ⇒ 麒麟控制端画出来的确实是那台机器的真实桌面（:0 锁屏界面）
