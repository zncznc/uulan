OS 认证模式：只认「系统账户名 + 该账户登录密码」，临时码保留为备路
生成时间：2026-11-19

一、用户口径的三次收窄（按时间顺序，最终形态）
  1. "只要输入被控机的用户名和密码就可以远程连"
  2. "继续，只要被控端用户名和密码 + 临时码"
  3. "取消临时码这个选项" → 随即"作为备用"
  最终：主路 = 用户名 + 系统登录密码；备路 = 一次性临时码（保留，可单独使用）。

二、架构上的硬约束（决定了实现形状，不是选择）
  PAKE 要求双方都知道那个秘密；被控端只能"验证"系统密码、不能"复述"它，
  所以 OS 模式天然用不了 PAKE —— 会话密钥只能是纯 DH。
  代价：**中继在理论上能中间人并看到系统登录密码**。直连没有中继，不受影响。
  这句话同时写在 config.rs 的 auth_os 注释与 session.rs 的 OS 分支处，不只写在文档里。

三、实现
  · 协议：新增明文一帧 AuthMode { os: bool }（只含布尔、不含秘密），DH 之后先声明
    走哪条路；被控端据此决定跑 PAKE 还是收 PamAuth。已验通的 PAKE 流程一行未改。
  · 被控端：--auth os|pake（落配置 auth_os，要求同时 --pam，否则明确拒绝并说明
    "没有校验手段"）；与管理参数一样"改完即退"。
  · OS 分支：允许名单 → PAM（未注入 checker 时回落 system_checker）→
    AuthOk{idx:0, proof:""}；**跳过 rekey**（同一把密钥计数器归零 = nonce 重用），
    控制端同步不 rekey。
  · auth_os 的主机上 P2 第二因素整套退场（否则临时码备路还要再输系统密码，
    那就不是备用入口而是同一个门）；HelloOk.pam_required = pam.enabled && !auth_os。
  · 控制端：有 --os-user 才走 OS 模式，且不再强制访问口令；面板里系统账户填了
    就不再要求临时码。

四、真机验证（麒麟 192.168.223.15，控制端/被控端同批新构建）
  · 主路（麒麟自身客户端 → 127.0.0.1:21117）：
      控制端：只给 --os-user zzz-not-a-real-user，无口令无临时码
      被控端：认证方式：系统账户口令（OS 模式…）→ OS 认证失败：系统口令不对
      控制端：被控端拒绝：密码不正确（0 秒自退，不干等）
  · 主路（Windows 客户端 → 直连）：同样 0.4 秒干净拒绝，日志同一行。
  · 备路（只给临时码）：鉴权通过 used_temp_code=true cred_slot=1 →
    已连上「麒麟真机」（linux 0.1.0，屏幕 1920x1080）→ 帧正常。
  · 全程使用"必然不存在的账户"做失败验证，**从未尝试 mis 的真实密码**，
    因此没有触碰任何真实系统账户的失败计数。

五、过程中抓到的真 bug
  主线传进来的是 pam_check: None（P2 里 pam_gate 遇 None 会回落 system_checker），
  我新写的 OS 分支把 None 当致命错误回了 AuthFail(NotAllowed)，
  表现为"账户明明在名单里却被拒绝、日志还看不出原因"。已按 pam_gate 的口径回落修复。
