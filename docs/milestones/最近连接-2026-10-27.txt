uulan · 控制端记住上次连接（--last / --forget）· 2026-10-27 夜间批（第二轮 05:00）

────────────────────────────────────────────────────────────────
一、为什么做这一项

上一轮把「我该连哪台」解决了（`--devices` 列中继知道的设备）。剩下的重复劳动是
**那个 9 位数字每次还要再抄一遍**：现场的做法往往是建一个便签、或者把
`--device 805747189` 整条命令存成脚本 —— 前者会过期，后者在被控端换机器/换 ID 之后
变成一条连不上的命令，而报错只会说「被控端不在线」。

所以这一项只做一件事：连成功一次之后，把「中继地址 + 设备 ID + 对端显示名」记在本机，
下次 `uulan-client --last` 直接用。它不是新的设备管理，**也不碰协议**。

────────────────────────────────────────────────────────────────
二、做法

新增 `crates/uulan-client/src/recent.rs`（纯逻辑 + 一个小文件）：

  Recent { server, device, host_name, saved_unix }
  路径：`$UULAN_CLIENT_CONFIG` > `$XDG_CONFIG_HOME/uulan/client.json` >
        `$HOME/.config/uulan/client.json` > `%USERPROFILE%\.config\uulan\client.json`
  （与 `uulan-host` 的 `host.json` 同一套约定；一台机器上现场只需要记一个目录）

控制端的三个入口：

  --last     只在命令行为空时补 --server / --device（`recent::apply` 是纯函数）。
             显式给的优先：`--last --device 111111111` 一定连 111111111。
  --forget   只删这个文件；不连中继、不要口令（「忘掉那台」正是发生在「口令不想留」时）。
  --devices  命中记住的那台，在那一行后面标「← 上次」；`--json` 保持中继原样，不加私货。

三条硬规矩（模块注释 + 测试都钉着）：

1. **口令绝不落盘。** 文件里只有 server / device / host_name / saved_unix。
   `saved_file_carries_no_credential` 把序列化结果的小写文本扫一遍
   （password/passwd/口令/密码/temp_code/secret/token/"value"），谁加凭据字段它立刻红。
2. **只在鉴权成功之后写。**「TCP 连上中继」不算：设备 ID 打错、口令打错时也会连上中继，
   把那种参数记下来，下次 `--last` 就是记下一个错答案。写盘失败只留一条 info 日志，
   绝不影响刚建立的会话（代价只是「下次还得手抄 ID」）。
3. **坏了就当没有。** 文件缺失 / JSON 坏 / 设备 ID 是空串 → `None` + 一句 stderr，
   `--last` 报「还没有记住任何设备」并让人去 `--devices`，不是抛错崩掉。
   老文件（没有 host_name / saved_unix 字段）照样能读 —— 否则每次升级现场都要手动删缓存。

其它细节：

- 写盘走 `*.json.tmp` + `rename`，Unix 下 `0600`（内容虽无凭据，
  「这台控制端连哪台机器」在隔离网里也值得少说一句）。
- `--last` 那行提示走 **stderr**：`--term` 模式下 stdout 是远端 PTY 的字节流，
  掺一行中文就等于往 shell 里凭空打了一行。
- 提示内容必须与真正用的参数一致：命令行已明确指了别台时印
  「上次连过的是 …；本次按命令行给的 --device 连」，不印「按 --last 用上次连过的」。

   **相关系数 0.9996、平均绝对误差 1.28/255 = 0.50%**（上轮基线 0.9989 / 0.51%）。

③ 真机自己编的控制端（麒麟侧，`UULAN_CLIENT_CONFIG=/tmp/uulan-client-test.json`）：
   - 首次连接（`127.0.0.1:21116`）29.0 fps，随后文件出现：
     `-rw------- mis mis 117` —— **0600**，内容同上；
   - `--last` 免参数再连：`按 --last 用上次连过的设备：805747189「麒麟真机」，刚刚`，
     首帧 261 ms、29.0 fps；

   - `--forget` → 「已忘掉上次连接的设备」，紧接着 `--last` 退出码 1 +

④ 反例（都要求「不覆盖、不凭空造」）：
   - 错口令（`--last` + 一个假口令文件）：`被控端拒绝：密码不正确`、rc=1，
     **配置文件 `saved_unix` 与 `device` 一字未变**；

   - 从来没有成功过时错口令：**不会凭空建出 `client.json`**；
   - 明文扫描：把口令串在 `client.json` 与四次运行的 RUST_LOG=info 日志里搜 ——
     **命中 0 个文件**。

五、边界与未验

- 只记**一台**（最后一次成功的那台）。要记多台就是「配置档」了，现场还没这个需求；
  现在换着连两台机器，`--last` 只认最近一次 —— 想固定就连时显式写 `--device`。
- 文件缺失/写不进去时 `--last` 会让人回退到手抄 ID，**不会**自己去猜中继上有哪台机器
  （那需要连中继拉目录，是另一件事）。
- 未验：窗口模式（默认开窗）下的 `--last` —— 它和 headless 共用同一份参数解析，
  本轮没单独开窗跑（`DESIGN.md` 里另一处已记录：验证 GUI 里程碑要 `painted=N`，
  而这一项不涉及渲染）。
- 未验：多用户机器上「A 用户的 client.json 会不会被 B 读到」—— 文件是 0600，
  但没人以另一个用户身份实测过。
