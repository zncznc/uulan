一、M4 剪贴板：麒麟 ↔ 麒麟跨显示整链（真 v4 加密链路）双向 ✅
---------------------------------------------------------------
测试台：scripts/remote-xvfb-testbed.sh（Xvfb :99 + 独立中继 127.0.0.1:21995 +
独立配置 /tmp/uulan-input-app/host.json，设备 460405305，全程不碰正式服务的身份与口令）。
控制端 = 真机自编 uulan-client（sha 前缀 ea34b9d6，v4）跑在**物理 :0**（剪贴板跟 $DISPLAY），
被控端 = 测试台 uulan-host `--capture x11::99.0`（剪贴板后端跟 capture 显示号走，
见 host/session.rs `params.capture.display()`）。两边是两条 X 连接上的独立进程。

判据（x11_clip_probe 当外部读写方，见 crates/uulan-clip/examples/）：
  1) :0  探针 SET `XCLIPA-1794409123`（探针自己 GET-BEFORE=none，基线不外推，符合设计）
  2) :99 探针 `GET-BEFORE len=17 <<<XCLIPA-1794409123>>>`   ← 方向 A 通（client→wire→host 写入）
  3) :99 探针顺手 SET `XCLIPB-1794409123`
  4) :0  探针 `GET-BEFORE len=17 <<<XCLIPB-1794409123>>>`   ← 方向 B 通（host→wire→client 写入）

统计（与判据互证）：
  控制端  剪贴板同步 : 发送 2 / 接收 1（本机写入失败 0 / 本机读取失败 0）
  被控端  剪贴板同步统计 sent=1 recv=2 errors=0 skipped_oversize=0 skipped_empty=0 skipped_same=44
  同场画面 解出 895 帧 / 丢帧 0 / 首帧 195ms / 29.8 fps（麒麟控制端照常）

诚实边界：判据探针与生产后端是同一份 X11 代码（uulan-clip），进程与 X 连接相互独立，
但独立性弱于 2024-10-24 那轮「与第三方 xclip 类外部客户端」互验；
**Windows ↔ 麒麟那半条仍未验**——夜批会话照旧拿不到系统剪贴板，控制端如实打印
「剪贴板不可用：OpenClipboard 失败（Win32 错误 5）」且**不声明 Cap::Clipboard**（10-31 改的行为，本轮再现 ✅）。
测试台已 down，/tmp/uulan-xclip 与脚本、真机与本机两侧口令临时文件均已删除。
