销掉的三格（DESIGN.md 里挂着「仍未验」的）：
  ① 播放延迟（下行：被控端出声 → 控制端信宿）——量出来了

一、方法（为什么不需要物理回路）
-----------------------------------------------------------------
白天班把「量播放延迟」记成阻塞：要「一端出声、另一端收声」的物理回路，而这台麒麟的
USB 声卡是 spdif 数字口（不接线回不到输入）。**这个结论只对物理声学与 Windows 侧成立。**
机内侧根本不需要空气回路：**信宿的 monitor 源就是数字回采路**——只要 aplay 真的把
PCM 交给了 PulseAudio 默认信宿，monitor 一定录得回来（11-17 那轮已把这个判据钉活）。
于是时间轴两端都有机器可查的时刻：
  · 锚点 = 两端 INFO 行的 UTC 时间戳（同一台机器同一时钟，无对表问题）：
      下行起算 T0 = 被控端「音频已开始（Opus/Ogg）」
      下行就绪 T1 = 控制端「实时播放已接上 program=aplay」
      上行起算 U0 = 控制端「麦克风转接已开始（Opus/Ogg 上行）」
      上行就绪 U1 = 被控端「麦克风转接已接上（解码器 + 本机播放后端就绪）」
  · 起声 = monitor 录回的波形上，该频率带通能量首次过半稳态的位置
      L_total = 起声 − T0（含编码器启动、编码、网络、解码、播放缓冲——「指令到出声」）
      L_tail  = 起声 − T1（播放后端就绪之后还剩多少——落地缓冲与解码尾巴）
  · 双向分开用不同频率：下行 440 Hz，上行 880 Hz（0.4 s 矩形窗里两者都是整周期
    = 176/352 个循环，Goertzel 数学正交，互不串扰）。
时间基：起声时刻 = parecord 首块数据落盘时刻 + 波形位置；不确定度 ±0.15 s
（落盘抖动与 onset 判据各占一半；onset 判据本身有 +0.10 s 的系统偏晚，
本机合成音硬起始标定后已扣除）。

两轮结论：**双向端到端延迟都 ≈ 1.2~1.3 s（±0.15 s），且几乎全部落在「播放后端就绪
→ 出声」这一段**（总延迟 ≈ 末端段，两轮一致）。方向之间 0.1 s 的差正好是一个判据
网格步长，两轮还互换先后 —— 即下行与上行延迟之差低于本台架分辨率。
这条把优化方向钉死了：**要降延迟先动播放命令的缓冲参数**（uulan-media::playback
的 aplay 候选，如 -B/-F 或换 period 大小），不是动协议、也不是网络段。

四、信宿争用（同脚本第 3 段，独立测试台 + 独立被控端 --once）
-----------------------------------------------------------------
下行 440 正在响时，用与本链路无关的 `paplay` 往同一信宿打 5 秒 1000 Hz：
  争用前 440 功率 = 1.975e+06 / 争用中 = 1.976e+06 / 争用后 = 1.975e+06（没塌）
  争用前 1000 ≈ 204 / 争用中 = 1.974e+06（跳变 >9000 倍，证明干扰音真进了这个信宿）
  控制端退出码 0，播放侧零句失败。
结论：这台麒麟（PulseAudio 13.99）上信宿是**混音共享**，不是独占抢占——uulan 的声音
不被挤掉、不收哑；「争用导致播放后端起不来/写入失败」的反例在这条信宿上构造不出来。
（多信宿机器仍是「只做了保守的默认信宿选择」，维持未验。）

五、本轮踩到并修掉的判据器/台架 bug（硬知识）
-----------------------------------------------------------------
1. **挂起的信宿连 monitor 都不吐样本**（11-17 记过现象，本轮才吃它的亏）：没人播时
   monitor 录出来只有 44 字节 WAV 头，「poll 文件增长定时间基」永远超时——表现像
   「parecord 坏了」，其实是信宿 IDLE。修法：预检段先挂一条 300 秒的**静音保活流**
   （ffmpeg anullsrc → paplay）把信宿钉在 RUNNING，再开录；静音流样本全零，
   不污染任何带通判据。
2. **pgrep 的 "aplay" 会把 paplay 数进去**（正则不锚定）：泄漏账一度把保活 paplay
   记成「aplay 泄漏」，差点写进报告当产品缺陷。计数一律 `-x` 精确进程名。
3. **awk -v 传算式会被当数字前缀截断**：`awk -v e="1795011493.88 + 2.3 - ..." 'BEGIN{printf "%.4f", e}'`
   只取第一个数（延迟显示成 1795011496.1798 才发现）。算式要放进程序文本：
   `awk "BEGIN{printf \"%.4f\", $expr}"`。
4. **同一行 local 互相引用**（白天「显示器选屏」五连修的坑，本轮第 N+1 次踩）：
   `local name="$2" lg="$WORK/$name.log"` 里 lg 拿到空 name → set -u 当场炸。
5. **timeout 杀 parecord 必回 124**：台架探活只看录回数据量，不看退出码。
6. onset 判据（0.4 s 窗能量过半）对硬起始恒偏晚 0.10 s：本机合成音标定后在判据器里扣除。
7. 独立起声的时间证明窗要两起声相隔 ≥0.3 s 才给得出；本轮两起声只差一个网格，
   该断言按纪律**自己 SKIP**（不当通过证据）。独立性由对照组（会话前 440/880 全静）
   ＋争用段 1000 Hz 的开关跳变＋矩形窗整数周期正交性共同支撑。
