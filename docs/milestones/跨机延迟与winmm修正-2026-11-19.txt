二、方法（scripts/verify-audio-cross-e2e.sh，Windows 侧编排）
-----------------------------------------------------------------
· 对表 scripts/clock-offset.py：常驻 `ssh kylin "while read; do date -u +%s.%N;
  done"`，逐轮喂行收戳，rtt 最小的 1/4 样本取中位当 offset、rtt/2 当不确定度。
  实测 unc 0.0021~0.0024 s，best_rtt 亚毫秒；跑前跑后各一轮，漂移 ≤0.0005 s。
  （每次新起 ssh 的老办法 rtt 里有 300ms 握手，Windows OpenSSH 又不支持
  ControlMaster —— 常驻会话循环是这台机上唯一能做到毫秒级的对表路。）
· 机内段：`TailWatch`（uulan-media::playback 纯状态机，时钟由调用方给，微秒）
  在 pump 里记「解码器就绪 → 首块 PCM 出解码器 → 首块 sink.write 返回」，
  外加逐块耗时（块数/平均/最大）。两句可 grep：
    实时播放首包已播完 dur_ms=NN
    播放末端统计 tail=首包解码=Nms 首包播完=Nms 块数=N 平均块=Nms 最大块=Nms
  原点未定时打「—」，不许编毫秒数（单测钉死三条迁移）。
· 跨机段：麒麟侧独立中继（绑 0.0.0.0:21995）+ 被控端测试台
  （--capture lavfi:testsrc2 + --audio-source lavfi:sine:440，独立配置/台账），
  Windows 控制端 --headless --seconds 18 --audio / --mic(lavfi 880)。
  下行 L = 控制端「首包已播完」(win 钟) − 被控端「音频已开始」(麒麟钟) − offset；
  上行 LU = 被控端「首包已播完」(麒麟钟) − 控制端「转接已开始」(win 钟) − offset。
· 口令只走 ssh 重定向进 0600 文件（先落 raw 再抽合格行，防 banner 污染）；
  远端台架脚本落文件 scp 过去再 bash（免嵌套引号被守卫拦）；收尾 kill 记名 pid。

三、实测（两轮一致，20 通过 / 0 失败 / 0 跳过 ×2）
-----------------------------------------------------------------
下行（麒麟起流 → Windows 首块在 waveOut 上放完）：
  R1 0.1274 s / R2 0.1620 s / 复跑 0.1535、0.1438 s（对表 ±0.002 s）
  分解（R1/R2）：本机末端段 54/54 ms（首包解码 32/27 + 首块等放完 21/26）
                 网络+管道+等起编 73/108 ms
  稳态：422 块 平均 59 ms 最大 64 ms；播放 2438688 字节 == 解码字节；错误 0；
        峰值 2945（与麒麟台架同源正弦）
上行（Windows 采集起 → 麒麟首块在 aplay 上写完成）：0.0811 / 0.0710 s
  ⚠ 锚点语义两个后端不同：waveOut 的「播完」=内核报 DONE=真放过；
  aplay 的「写完成」=进 ALSA 缓冲。上行的「空气里响了」仍以 11-18 monitor
  台架的 ~1.2 s 为准 —— 别拿 0.07 s 当麒麟出声延迟。

结论排序：麒麟侧 1.2 s 的瓶颈在 Pulse 缓冲（11-18 结论不动），Windows 侧
waveOut 逐块等放完的纪律把末端段压到 ~50 ms 量级 —— 同一份 pump 代码、
两种播放语义，这就是跨机数据比机内数据多出来的信息。

四、首跑撞掉的真产品 bug（winmm WAVEHDR）
-----------------------------------------------------------------
首跑 10 通过 / 5 失败，红在「实时播放首包已播完」缺失 —— 查日志不是台架：
  WARN 播放后端写入失败 error=waveOutPrepareHeader 11
MMRESULT 11 = MMSYSERR_INVALPARAM。根因：WaveHdr 把 flags/loops 两个 DWORD
紧跟 bytes_recorded 写，而真 WAVEHDR(x64) 在它们之间夹着 DWORD_PTR dwUser
（8 字节）—— 内核把指针碎片当 dwFlags。修正后加断言钉死：
  size_of::<WaveHdr>()==48；flags@24、user@16、loops@28、next@32、reserved@40。
**Windows 侧 --audio 此前从没真出过声**：历轮所有「音频 ✅」的证据链都走
--audio-save（WAV 落盘）或麒麟 aplay，结构体从没被真驱动校验过 —— 又一课：
**「测试路径」与「用户路径」不一致时，测试绿不等于用户能用**。

五、判据器自身的坑（本轮新账）
-----------------------------------------------------------------
1. 收工摘要打的是**最后相位**（正常跑完 Ended）—— 判「到过 Running」必须
   grep 状态迁移行「被控端正在推流」，别 grep 摘要行（首版台架就这么假红过）。
2. 对表脚本的 `while read` 远端循环必须 `ssh -T` 去 PTY；stdout readline
   无超时 —— 只用于「起得来、回一行」的可信通道，别拿去当常驻探针。
3. awk -v 传算式截断坑复现区：算式一律放 BEGIN 程序文本（calc() 沿用）。
4. 3b 段差点把「麦克风转接已开始」的锚点变量起名 U1 —— U1 在上面已经是对表
   不确定度（同名互相覆盖是台架老事故族，本轮第 N+2 次）。改 UP*/UPE。
5. `use tracing::info` 不加 cfg：Windows 上零警告、麒麟上 unused 警告 ——
   跨平台 import 必须跟着用处挂 cfg，**每个目标平台都至少 check 一遍才算数**。
