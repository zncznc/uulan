麦克风转接（M7 上行：控制端 → 被控端的音箱）· 2026-11-18 夜批（01:00 班接线，05:00 班真机验收）
================================================================

本轮把 DESIGN 里挂了两周的「M7 剩下的唯一一格」补上：控制端操作员对着自己机器的
麦克风说话（或送任意采集源），声音从**被控端**的音箱放出来。「UU 远程」式的隔空喊话。

一、这一格为什么现在才做、以及为什么长这样
--------------------------------------------
* 通道零新增：audio 通道（协议 v4 的第 4 条）两个方向的密钥与 nonce 计数器本来就
  分开派生（crypto::ChannelKeys），**上行只是往同一条 TCP 的另一半写字节**。
  PROTO_VERSION 保持 4，四条通道的集合没动。
* **协议里没有 MicStop**（这是本轮刻意的设计，不是遗忘）：
  「停」= 控制端结束采集 → 上行写半端 drop → TCP 写半边关闭 → 被控端 read_frame
  拿到 EOF → 收尾。给「会话中途用户关麦克风」这种**还不存在的 UI** 预留一条消息，
  就是历轮点名一直在清的「协议先行、两端未接」。等 UI 出现的那天，消息、构造点、
  处理点必须同一批落地。
* **running:true 的口径 = 对面「解码器 + 播放后端都起来了」**，不是「收到消息了」。
  实现：pump 在 ffmpeg spawn 成功后经 channel 转达（`on_ready` 回调跨阻塞/异步边界）。
  被控端在 Windows 上如实回 `running:false`（共享播放层在 Windows 没实现，
  控制端自己的 waveOut 在客户端 crate 里）—— 不许装作播了。
* MicState 观察器**复用** AudioWatch 状态机（消息形状 running/codec/detail 完全同构），
  但**每台只管一条流**：控制端为下行/上行各持一份。新增一个相位 LocalDead：
  「本机采集没起来（没发请求）」——自己没起来 ≠ 对面起不来（Failed），两种红
  在统计行上必须分得开。
* **播放层下沉到 `uulan-media::playback`**（本轮唯一的重构）：
  控制端 audioin 的「Ogg → ffmpeg 解码 → 播放后端」与被控端 mic 收的是同一条流，
  2026-11-17 真机实测出的全部纪律（paplay 不吃 raw、尾巴 1500ms 宽限、
  **播放侧先死必须先杀解码器**否则三方互等挂死整个进程）从两份变一份。
  两句可 grep 证据「实时播放已接上 / 已收尾」原样保留（老验收脚本不破坏）。
  原 audioin 的两条纯函数单测随代码搬家（名字没改）。

二、采集源口径（--mic / --mic-source / --mic-bitrate）
------------------------------------------------------
* Windows 默认：DirectShow **没有免枚举的默认设备**概念 —— 起一次
  `ffmpeg -list_devices true -f dshow -i dummy` 从 stderr 取第一个音频设备名
  （`parse_dshow_audio` 纯函数 + 真机格式样例测；注意这条命令**必定非零退出**，
  判据只有 stderr 的设备表，拿退出码判成败会把所有枚举都判成失败）。
  本机（ZNC-7G4D）实测**没有任何录音输入设备** —— 默认枚举路径走到就是
  「这台机器没有可用的录音输入」这句实话。
* unix 默认：`pulse:default` = PulseAudio 默认输入源（麦克风）。
* `lavfi:` 合成源带 `-re`（不加会拼尽全力灌爆链路 —— 下行同款坑）。
* **本机采集起来了才发 MicStart**（与下行「先起接收端再发 AudioStart」同一时序
  纪律的两个方向）：对面不许为一条永远不来的流白起管道。源名不带前缀 = 直接报错
  （猜设备名的表现是「采集到了别的东西」，比报错难查十倍）。
* 上行编码钉死 48 kHz / 立体声 / libopus/ogg / lowdelay / frame_duration 20 /
  page_duration 20000 + flush_packets 1 —— 对面解码器与 aplay 只认这一种格式，
  单测钉住（mono 上行 = aplay 按立体声播 = 变速+串声道，同「缩放差 1 像素花屏」族）。

三、配置闸门
------------
* 被控端 `mic_sink`：只认 `speaker`（默认）与 `null`（解码后丢弃，验收台专用 ——
  没声卡的机器也能把「上行 → 解码 → 统计」整条钉住）。**拼错词让服务起不来**
  （ConfigError::MicSink，power_allow 同纪律）。老 host.json 缺这个字段照常起
  （serde default，真机测试台已按此跑）。
* `--diagnose` 加第九项「麦克风转接」：只问 aplay 在不在 PATH（**只读**，
  自检不许顺手出声），没有 = WARN 不是 FAIL。

八、判据器的真 bug：交织立体声喂 Goertzel（05:00 班，第二轮红挖出来的）
--------------------------------------------------------------------
* 现象：同一测试台两轮，旧判据器给出 ratio=36 与 ratio=0.7 —— 后者把
  「440 Hz 是主角」判成失败，而被控端侧全部管道账目（收字节 / 解码峰值 2945 /
  pcm==played / 12 秒量级的上行流）都证明声音在响。
* 根因：旧 check440 直接拿**交织立体声的 short 序列**按 `rate=48000` 跑 Goertzel。
  short 流每秒 96000 个，440 Hz 的真实音在错误时间基下落在 220 Hz —— 探 440 探的
  其实是次谐波泄漏，**比值沦为窗口相位对齐的抽签**（第一轮恰好抽中高值）。
  混成单声道帧后再探同一份字节：4.7e7× / 8.3e7× —— 稳定九个数量级。
* 修法（两条脚本同修：verify-mic-realkylin-e2e.sh 与 verify-audio-playback-e2e.sh）：
  先把 (L+R)/2 混成帧，窗口 `w = rate*2` 帧（两秒），判据 `peak>100 且 ratio≥10`
  原样不动 —— 修的是测量，不是门槛。顺带给 mic 脚本补了缺失的 `skip()`（EXT 模式
  5b 分支撞 command-not-found）。
* 复跑证据：修正后 mic e2e 两轮 **18/0/0 一致**；`verify-audio-playback-e2e.sh`
  （下行播放老验收，同一判据器家族）复跑 **15 通过 / 0 失败**，录回比值 3.36e7 倍、
  同会话画面 2532 帧 / 丢帧 0 / 首帧 116 ms —— 老脚本没有被这次修正打坏，
  而且从「抽签」变成了「钉住」。
* 教训入册：**判据不稳先怀疑判据器**。凡是「同一链路两轮差一个数量级」的声学比值，
  先检查采样率/声道口径，再谈产品回归（同 11-16「paplay 假绿」、11-17 夜批
  「台架自身 bug 伪装产品缺事件」一族）。
