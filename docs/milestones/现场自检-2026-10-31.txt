验收脚本 `scripts/verify-diagnose-e2e.sh`（真机 16/16 断言全过）
---------------------------------------------------------------
正例（真 server + `--capture x11`）：
- 退出码 0、结论行「可以跑」、八项里 7 项 `[ OK ]`、`显示` 是 WARN（锁屏）

反例（各自只坏一项，必须指对那一项且退出码 1）：
- `DISPLAY=:77` → `[FAIL] 显示  打不开 X 显示 :77`（并给出「确认图形登录 / DISPLAY 与 XAUTHORITY」的建议）
- `--ffmpeg /bin/false` → `[FAIL] ffmpeg  /bin/false 跑不起来（-version 退出码 1）`
- `--server 127.0.0.1:1` → `[FAIL] 中继  连不上 127.0.0.1:1：Connection refused (os error 111)`

秘密不外泄：四份自检输出里拿 `host.json` 的 password 原值 grep，**命中 0 次**；
身份行只给设备 ID（本来就可公开）、临时码与注册令牌只给「有 / 无」。

同轮修掉的两个「看起来能用」的判定
----------------------------------
1. **`--ffmpeg` 指错程序**：`cmd.exe` 这类程序也「成功退出 + 打一行版本」，只看退出码会把
   它当成好 ffmpeg。现在要求 `-version` 首行含 `ffmpeg version`，否则直接 FAIL。
2. **编码器列表按整词比对**：只带 `libx264rgb` 的 ffmpeg 不能顶替 `libx264`
   （`contains` 会误判），单测钉住。
3. 内存数字第一版错了（`parse_meminfo` 返回的是**字节**，被当成 kB 又除了一次 1024，
   显示成「可用 32794476 MB / 共 3887912 MB」）。真机第一次跑就露出来，已改成
   「已用 3791 MB / 共 32025 MB」，并让单测拿样例 `/proc/meminfo` 覆盖 KB→MB 那一步。
