uulan · 「重连次数用尽 → 退出码 4」真机验收 · 2026-10-30 夜间批

背景：这条路径一直只有单测与本机 e2e 覆盖（`Reconnect` 纯逻辑 + 窗口 `about_to_wait` 的
`Finished` 分支）。真机不好造「中继长时间不回来」：正式中继有 `Restart=always`，停不掉
（`systemctl --user stop/start` 在无人值守 cron 里还会被拦）。这一轮换成**自己起的中继**。

一、做法（`scripts/verify-reconnect-giveup-e2e.sh`，无人值守可跑）

  1. 真机上起测试台（`scripts/remote-xvfb-testbed.sh up`）：Xvfb :99 + 独立 relay(:21995) + 独立 host。
     正式服务（:21116）全程没动。
  2. Windows 控制端 headless 连上去：`--headless --seconds 120 --reconnect 1`，等它真出画面。
  3. `kill` 掉测试台中继的 pid（只杀自己起的那个进程，不碰 systemd 单元）。
  4. 客户端只重试一次 → 连接被拒 → 放弃。

二、实测结果（真机麒麟 V10 SP1，Windows 控制端）

  客户端退出码 = **4**
  stdout：
    不再重连
    会话       : 建立 1 条 / 断线接回 0 次
    会话没能接回：连续重连 1 次都没接回（最后一次：会合失败: io: 由于目标计算机积极拒绝，无法连接。 (os error 10061)）
    解出帧 380 / 丢帧 0 / 首帧 200 ms（统计段照旧打印）
  脚本断言 4/4 通过，退出码 0。

三、同轮修掉的真问题

  **headless 以前在「放弃重连」时也退出码 0**：只打一句 `不再重连`，然后照常出统计并 `Ok(())`。
  夜批/脚本因此分不清「按 `--seconds` 跑完了」和「画面早就冻住、重连也放弃了」。
  现在 headless 与窗口模式一致：放弃 → `eprintln!("会话没能接回：{原因}")` + `exit(4)`。

  回归对照（同一构建）：正常 `--headless --seconds 10` 打真机 :0 → 退出码 **0**、
  354 帧 / 丢帧 0 / 28.6 fps（与改动前一致）。

四、边界

  - 只验了「连接阶段被拒」这一类放弃（中继不在）；「会话中途反复失败再放弃」的退避阶梯
    （1/2/4/8/15 s）仍以单测 + 本机 e2e 为准，真机没逐级跑过。
  - 真机上 `kill` 的是**测试台中继**，不是正式服务；正式服务的 `Restart=always` 与
    「中继重启后自动接回」另有 2026-10-26 的真机实测（4.3 秒接回）。

五、脚本化

  `scripts/verify-reconnect-giveup-e2e.sh` —— 起测试台 → 跑会话 → 杀中继 → 断言退出码 4 与三句输出。
  踩坑：退出码不能靠「另起一个 shell 去 `wait`」拿（bash 会报 `pid … is not a child of this shell`，
  RC 变成 127）；要把客户端包在一层子 shell 里，由它把 `$?` 写进文件再轮询。
